# ステージ3「炎上する宿場」

ユーザーが差し替えた背景（コミット `70f994e`）に合わせて、道路・建物の通行禁止範囲・開始位置・出口・炎・柵を再配置しました。画像とその.metaは変更していません。Spriteが複数モードへ変わっていたため、背景と年表アイコンの参照先を新しいSpriteのfileIDに修正しました。

## 進路の仕組み

**柵を燃やすだけで裏道へ自動切り替えする処理は廃止しました。**

ステージ3の信長は、現在位置から右上の出口までGridPathfinder2Dで探索します。固定の中間地点へ引き戻されず、0.25ゲーム内秒ごとに経路全体が通れるか確認し、塞がれたときに探し直します。通れる経路を毎回作り直す処理は廃止しました。風で分岐の上へ押されると、その位置から近い裏道へ進めます。本通りを塞ぐと、開いている裏道へ迂回します。両方の道が塞がれば待機し、道が開けば再探索で進みます。

ステージ1・2は従来の経由地点方式を維持しています。

風は斜めを含む自由な方向へ指定できます。風の勢いが残っている間は通常歩行が逆らわず、落ち着いた位置から再探索します。分岐の入口を広げ、壁に当たったときは壁沿いに滑るよう修正しました。精査の詳細は [ステージ1〜3の修正記録](STAGE_REVIEW.md) を参照してください。

## 配置と遊び方

- **開始**：左の橋の上。**出口**：画像で赤丸を指定した右上の道（背景ピクセル約1416,100／ワールド座標5.8,3.705）。
- **本通り**：中央の宿の下側。2か所の炎を雨で消して進めます。火に触れると失敗。自然消火はしません。
- **裏道**：中央の宿の上側。上の道にある固定柵を雷で燃やし、3秒待つと通れるようになります。開通しても、その時点で本通りの方が近ければ信長は本通りを選びます。
- **風で信長を誘導**：固定柵を開通させた後、中央の宿の左側にある分岐で信長を上方向へ押します。分岐を過ぎる前に操作すると裏道へ誘導しやすくなります。
- **風で通行止め**：右下の道の広がった場所に、青みのある縦向きの可動柵があります。風で左下へ押して本通りの狭い部分を塞ぐと、信長は開通した裏道へ迂回します。柵は壁や信長へめり込まない位置で止まります。
- **濡れ**：固定柵を雨で濡らすと乾くまで雷で着火できません。燃焼中に雨を当てると消火され、開通しません。可動柵は風だけで動かす障害物です。
- 能力は **風3・雷2・雨2**。信長への雷、炎への接触、45秒経過で失敗します。

可動柵を動かす風の範囲に信長も入れると、信長も同じ方向へ押されます。道を早めに塞ぐ方法と、分岐で信長を直接誘導する方法を使い分けてください。

難易度は単一構成です。ノーマル／ハード切替・延焼は未実装です。操作中は移動・燃焼・可動柵がスローになりますが、制限時間も同じスロー速度で減ります。

## Unityで確認する手順

1. GitHub Desktopで `feature/stage02-layout` をPullし、Unity **6000.3.21f1** で開きます。
2. `Assets/Project/Scenes/GameScene.unity` → **StageLoader** → **Use Editor Test Stage** をオン、**Editor Test Stage Id = 3** でPlayします。
3. 新背景の橋に信長、上の道に固定柵、下の道に炎2つ、右下に可動柵が表示されるか確認します。
4. 雨で炎を消し、本通りから出口へ進めるか確認します。
5. リトライし、雷で上の固定柵を開きます。**開通だけでは強制的に上へ曲がらないこと**を確認します。
6. 分岐の手前で信長へ上向きの風を当て、押された後に本通りへ引き戻されず、裏道へ進むか確認します。
7. リトライし、右下の可動柵を左下へ押して本通りを塞ぎます。固定柵が閉じている間は停止し、雷で上を開通すると裏道へ進むか確認します。逆方向の風で可動柵を退かしたときにも再探索するか確認します。
8. 柵が移動中・燃焼中・信長が迂回中にポーズ→再開。位置・燃焼時間が停止し、再開後に続くか確認します。
9. 失敗・クリア・移動中からリトライ。信長が橋へ戻り、可動柵が初期位置、固定柵と炎が復元され、能力回数も戻るか確認します。信長の失敗イラストは開始まで維持されます。
10. 年表への移動とクリア記録、ステージ1・2の経由地点移動・風・リトライを回帰確認します。確認後はテスト設定をオフに戻してください。

通常はステージ2クリア後に年表から選択できます。

## 検証済み・未検証

`Tools/validate_stage03.py` で、保存された障害物と信長の半径0.4＋余裕0.02を使ったグリッド探索を実行しています。

- 初期配置：本通りの経路がある。
- 上の固定柵を開通：新たに探索すると裏道が短くなる。移動中の有効な経路を強制的に切り替える処理はありません。
- 信長の位置を上の分岐へ移す：裏道を選択。
- 可動柵で本通りを塞ぎ、上を開通：裏道を選択。
- 両方を塞ぐ：経路なし。
- 可動柵の初期位置から通行止め位置までの形状の通過幅、信長を上の分岐へ押す区間の通過幅。
- Spriteサブアセット、Prefab内参照、能力レイヤー、HUDの日本語文字。

ステージ2の静的検査、C#40本の構文解析、23シーン／PrefabのYAML・Component・親子参照、各ステージのCamera・AudioListener・EventSystem・SceneAudioが1つであることも検証しています。

**Unityでのコンパイル・実際の風による物理移動・入力・攻略可能性・聴感確認は未実施です。** グリッド検査はUnityのCollider.Castや実機の代用ではありません。

BGM・通常SEは既存設定を継続。炎・雨のループ音源は未割り当てです。各FireVisualのTenyuEffectLoopSound → Loop Clip、共通RainEffect.prefabのLoop Clipへ音源を割り当てて確認してください。

### ゴール位置と角の停止の追加修正

右上の指定位置へ目的地とゴールColliderを移動し、右側から続く道路のColliderを更新しました。ステージ3の経路確認には0.05の先読み余裕を追加し、右下の可動柵の待避場所も少し広げています。

経路の角に0.025以内まで近づいただけで次の点へ進める処理を修正しました。次の区間を体が通れる場合だけ省略し、通れなければ角まで進みます。毎フレーム遠い点を探して経路を切り詰める処理も除去しました。

ステージ3のSceneビューでは、実際には使わない中間経由地点の赤い線を描かず、開始位置を水色、ゴールを黄色で示します。Play中の緑の線が実際に探索した経路です。

PlayModeテストに `NearCornerDoesNotSkipIntoAnObstructedNextSegment` を追加しました（クラウドでは未実行）。Unityで分岐の手前から右上の出口までを確認してください。
